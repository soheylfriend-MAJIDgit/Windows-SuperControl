# Windows SuperControl ۲٫۰

یک رابط **pywebview** (زیبا، RTL، تم روشن/تاریک) که پوشهٔ گوگل درایو را
**در سطح شبکه** پایش میکند و فایلهای کد پایتونی تازه یا ویرایششده را
یا فوراً اجرا میکند یا با تأیید شما اجرا میکند.

> هستهٔ برنامه دقیقاً **یک تاگل** است: **«اجرای خودکار کدهای جدید»**.

---

## ۱. نصب و اجرا (ویندوز)

۱. این مخزن را دانلود کن (`Code → Download ZIP`) و از حالت فشرده خارج کن.
   همان پوشهای که قبلاً `run.bat` توش بوده، همهچیز همانجاست.
۲. پایتون ۳٫۹ یا بالاتر نصب داشته باش (از `python.org`؛ حتماً تیک
   **Add Python to PATH** را بزن).
۳. **`setup_shortcut.vbs`** را دوبار کلیک کن → یک شورتکات
   «Windows SuperControl» روی دسکتاپ میسازد.
۴. روی آن شورتکات دوبار کلیک کن. پنجرهٔ برنامه باز میشود.

همچنین میتوانی مستقیم **`run.vbs`** را دوبار کلیک کنی. همان نتیجه را میدهد.

### نصب pywebview (اختیاری)

```
run.bat install
```
یا `py -3 -m pip install --user pywebview`.

اگر `pywebview` نصب نباشد، برنامه خودش تلاش میکند نصبش کند؛ اگر نشد،
**همان رابط** را با مرورگر پیشفرض ویندوز (Edge/Chrome) باز میکند.
یعنی در هر حالت ظاهر و عملکرد یکسان است.

---

## ۲. پنجرهٔ مشکی cmd کجا رفت؟

- لانچر واقعی **`run.vbs`** است. این فایل پایتون را با
  `WshShell.Run(cmd, 0, False)` اجرا میکند؛ یعنی **پنجره مخفی** است و
  `wscript.exe` اصلاً کنسولی ندارد. هیچ پنجرهٔ مشکیای باز نمیشود.
- **`run.bat`** فقط برای سازگاری نگه داشته شده: بلافاصله `run.vbs` را اجرا
  میکند و خارج میشود (ممکن است یک چشمک خیلی کوتاه cmd ببینی).
  **برای صفر شدن کامل پنجرهٔ مشکی، از `run.vbs` یا شورتکات دسکتاپ استفاده کن.**
- خطاها دیگر توی کنسول گم نمیشوند. همهچیز در
  `%APPDATA%\WindowsSuperControl\launch.log` نوشته میشود و اگر برنامه
  اصلاً بالا نیاید، `run.vbs` یک پیام خطای ویندوزی نشان میدهد.
- فقط وقتی **خواستی** کنسول ببینی: `run.bat diagnose`.

## ۳. منطق اصلی (مهمترین بخش)

### تاگل «اجرای خودکار کدهای جدید»

| حالت | رفتار |
|---|---|
| **خاموش (پیشفرض) = دستی** | هر فایل کد تازه/ویرایششده بلافاصله در لیست «کدها» ظاهر میشود، ولی **اجرا نمیشود** تا دکمهٔ **«بله اجرا کن»** یا **«نه اجرا نکن»** را بزنی. |
| **روشن = خودکار** | همان فایل **بدون هیچ پرسشی فوراً اجرا میشود.** |

نکتهای ریز: اگر حالت دستی بودهای و چند مورد «منتظر تأیید» داری، روشن کردن
تاگل آنها را ناگهانی اجرا نمیکند؛ آنها همچنان منتظر میمانند و فقط
**تشخیصهای بعدی** خودکار اجرا میشوند. (برای امنیت بیشتر.)

### پایش در سطح شبکه

- پایش از روی پوشهٔ لوکال `G:\My Drive\Windows-SuperControl` انجام **نمیشود**.
- برنامه هر ۴ ثانیه (قابل تغییر: ۲ / ۴ / ۱۰ ثانیه) لیست عمومی پوشهٔ درایو را
  از `https://drive.google.com/embeddedfolderview?id=...#list` میخواند،
  سپس محتوای هر فایل کد را دانلود و **SHA-256** آن را محاسبه میکند.
- چون زمان نمایشدادهشده در لیست درایو دقیقهدقیقه است، برای اینکه ویرایشهای
  پشتسرهم جا نمانند، محتوا هر بار دانلود و هش میشود. نتیجه: ویرایش یک فایل
  حتی در همان دقیقه هم **بلافاصله** بهصورت «تغییر کرده» دیده میشود.
- وضعیتها: «جدید»، «تغییر کرده»، «منتظر تایید»، «در حال اجرا»،
  «اجرا شد»، «خطا»، «رد شد»، «حذف شده».

### کدام فایلها اجرا میشوند؟

فقط فایلهایی که نامشان به **`.py.txt`** ختم شود. بهصورت پیشفرض
`main.py.txt` مستثناست. بنابراین `config.txt`، `name.txt`، `dialog.txt`،
`Code.gs.txt` **هیچوقت اجرا نمیشوند**. قبل از اجرا میتوانی دکمهٔ «نمایش کد»
را بزنی و هش SHA-256 را ببینی.

> ⚠️ **امنیت:** حالت خودکار یعنی اجرای خودکار کد از روی درایو. فقط وقتی
> روشنش کن که مطمئنی جز خودت کسی نمیتواند توی آن پوشه فایل بگذارد.
> دسترسی لینک عمومی پوشه الان **فقط خواندنی (reader)** است.

### اجرای کد

- هر کد توی کش محلی (`%APPDATA%\WindowsSuperControl\cache\<id>.py`) ذخیره
  میشود و با همان مفسر پایتون اجرا میشود.
- `stdout` + `stderr` داخل کارت فایل نمایش داده میشود، بههمراه
  **زمان اجرا بر حسب میلیثانیه**.
- مهلت اجرا پیشفرض ۶۰ ثانیه و حداکثر اندازهٔ فایل ۲۰۰ کیلوبایت است
  (هر دو در `config.txt` قابل تغییر).
- فرآیند فرزند هم با `CREATE_NO_WINDOW` اجرا میشود، پس کد هم پنجرهٔ مشکی
  باز نمیکند (کدهای tkinter/GUI هم درست کار میکنند).

## ۴. بخش «دیالوگ» (ارتباط از راه دور)

تب **💬 دیالوگ** یک صندوق پیام مستقیم از درایو است:

- برنامه فایل `dialog.txt` همان پوشه را پایش میکند. هر پیامی که آنجا نوشته
  شود (حتی از طرف ایجنت توی چت)، در این بخش ظاهر میشود.
- فرمت `dialog.txt` ساده است و از چند پیام پشتسرهم هم پشتیبانی میکند:

  ```
  id=1
  from=Arena Agent (chat)
  type=yesno
  question=ارتباط برقراره؟
  note=یک توضیح کوتاه
  answer=

  id=2
  from=Arena Agent
  type=yesno
  question=همهچیز خوبه؟
  answer=
  ```

- دکمههای **«بله، ارتباط برقراره»** و **«خیر، مشکل دارد»** پاسخ را ذخیره
  میکنند. پاسخ در سه جا نوشته میشود (هرکدام که در دسترس باشد):
  1. `%APPDATA%\WindowsSuperControl\dialog-answer.txt`
  2. اگر Drive for Desktop داری: `G:\My Drive\Windows-SuperControl\dialog-answer.txt`
     → خودش سینک میشود و ایجنت مستقیماً میخواندش.
  3. اگر `WEBAPP_URL` در `config.txt` تنظیم شده باشد: با POST به وب اپ Apps Script.

  الان `WEBAPP_URL` خالی است، پس مسیرهای ۱ و ۲ کار میکنند؛ تب دیالوگ
  دقیقاً میگوید پاسخ کجا ذخیره شده.

## ۵. ظاهر (دیزاین سیستمی که خواستی)

- RTL کامل، فونت **Vazirmatn**، اعداد و تاریخ **فارسی/شمسی**.
- تم **تاریک بهصورت پیشفرض** + دکمهٔ تغییر تم (بالا سمت چپ).
- متغیرهای CSS: `--bg`, `--surface`, `--surface-2`, `--border`, `--border-strong`,
  `--text`, `--text-dim`, `--accent`, `--accent-soft`, `--danger`, `--urgent`,
  `--due`, `--done`, `--canceled` و رنگهای `*-soft` متناظر.
- تبها بهصورت **قرص (pill)**، کارتها، چیپهای فیلتر، تگهای وضعیت معنایی،
  تاگل بزرگ، تأیید درونخطی، و جدول گزارش.
- **بدون سایههای سنگین و بدون گرادینت** (فقط یک گرادینت خیلی ملایم روی لوگو).
- واکنشگرا تا ۳۹۰px (موبایل) و ۱۴۰۰px به بالا.
- بدون خطای console: همهٔ تماسها یا از `window.pywebview.api` هستند یا
  از `/api/<method>` روی سرور محلی.

## ۶. فایلهای مخزن

| فایل | کارش |
|---|---|
| `bootstrap.py` | هستهٔ برنامه: پایش شبکه، هش، اجرا، دیالوگ، سرور fallback |
| `ui.html` | کل رابط (HTML/CSS/JS) — همان فایلی که pywebview نشان میدهد |
| `run.vbs` | لانچر **بدون کنسول** (فایل اصلی برای اجرا) |
| `run.bat` | لانچر سازگاری + `run.bat install` + `run.bat diagnose` |
| `setup_shortcut.vbs` | ساخت شورتکات دسکتاپ بدون کنسول |
| `config.example.txt` | نمونهٔ تنظیمات (اسمش را بگذار `config.txt`) |
| `requirements.txt` | `pywebview` (اختیاری) |
| `tests/test_core.py` | ۳۲ تست بدون GUI (`python -m unittest discover -s tests -v`) |

خروجیهای برنامهای توی `%APPDATA%\WindowsSuperControl\` ساخته میشوند:
`state.json`, `cache/`, `launch.log`, `dialog-answer.txt`, `started.flag`.

## ۷. تنظیمات

همهچیز پیشفرض دارد و نیازی به تنظیم نیست. برای تغییر،
`config.example.txt` را به `config.txt` تغییر نام بده و ویرایش کن.
مهمترین کلیدها:

| کلید | پیشفرض |
|---|---|
| `FOLDER_ID` | `1PmMAu537pzN3mjKf_PYctUOlbOIQCUf1` |
| `POLL_SECONDS` | `4` |
| `CODE_SUFFIX` | `.py.txt` |
| `EXCLUDE` | `main.py.txt` |
| `DIALOG_FILE_ID` | `10z2lb0jbThUh8kaWERYUttxudeCzX-Wf` |
| `LOCAL_DRIVE_PATH` | `G:\My Drive\Windows-SuperControl` |
| `WEBAPP_URL` / `WEBAPP_SECRET` | خالی |
| `MAX_CODE_BYTES` / `RUN_TIMEOUT` | `200000` / `60` |

اولویت: `config.txt` لوکال → `config.txt` داخل درایو → مقادیر پیشفرض.

## ۸. عیبیابی

```
run.bat diagnose
```
این دستور لیست فایلهای پوشهٔ درایو، دانلود `config.txt`، وضعیت pywebview
و متدهای API را چاپ میکند. لاگ کامل همیشه اینجاست:

```
%APPDATA%\WindowsSuperControl\launch.log
```

اگر پنجره باز نشد: `run.vbs` پیامی نشان میدهد که میگوید پایتون پیدا نشد
یا برنامه استارت نخورد. معمولاً نصب دوبارهٔ پایتون با تیک PATH حلش میکند.

## ۹. تستها

```
python -m unittest discover -s tests -v
```
۳۲ تست، شامل: پارس لیست درایو، تشخیص فایل جدید/ویرایششده، حالت دستی
(بدون اجرا تا تأیید)، حالت خودکار (اجرای فوری)، رد کردن، خطا و زمانسنجی،
ذخیرهٔ پاسخ دیالوگ، لیست سفید API، سرور fallback روی HTTP، و بررسی
محتوای `ui.html`.

> تستها بدون pywebview و بدون شبکه اجرا میشوند (درایو mock شده است)،
> پس توی لینوکس/مک هم سبز هستند.
